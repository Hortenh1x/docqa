# Реальный AI-прогон — 2026-09-10

Разрешение владельца: около $3 на тест. Израсходованную сумму оцениваем по provider
usage и максимальным тарифам без скидок: **$0.39736278**. Это верхняя тарифная оценка,
не выписка из кабинетов; скидки cache/off-peak могут сделать списание меньше.
Суммарный предварительный консервативный резерв всех вызовов **$2.31703162 < $3**.
Неразобранного usage нет. Лимит относится к этому прогону, не является глобальным
лимитом приложения, который владелец явно попросил не вводить.

## Метод и воспроизведение

Команды из корня проекта:

```sh
.venv/bin/python -m audit.paid_eval --run
.venv/bin/python -m audit.paid_eval --run --correct-german
```

Повтор при уже существующем ledger запрещён самим runner; нельзя удалять ledger
и считать, что общий разрешённый бюджет обнулился. Корректирующий прогон переносит
все резервы/usage первого и работает в пределах тех же $3. Ключи читаются из `.env`.
В stdout/evidence нет API keys, headers или DSN. Перед платными вызовами проверены
offline pre-call rejection, отсутствие возврата резерва, allowlist хоста/endpoint
и обнаружение превышения provider usage над оценкой.

Три синтетические коллекции копируются из локальной dev БД с READ ONLY transaction
в disposable PostgreSQL18/pgvector. Только выбранные tenants/collections/documents/chunks,
без api_keys, queries и чужих коллекций. Текущие миграции применяются к временной БД.
Хэши исходников, corpus chunks и количество строк записаны в metadata.json.
Исходная БД, production и файлы пользователей не меняются. Временные контейнеры удалены.

Пройдено 65 воспроизводимо выбранных вопросов (5 из каждой из 13 категорий v2;
seed 20260910) и весь access set из 32 вопросов. Потом перепроверена немецкая пара
доступа: **99 исполнений, 97 уникальных сценариев**. Конкурентность answer/judge=3.
Все 440 provider HTTP requests получили 200; сетевые/провайдерские ошибки не скрывались.

Стек: текущий pipeline с `.env`, OpenAI text-embedding-3-small@1024,
DeepSeek alias deepseek-v4-flash, no reranker, gate0.28, top_n20, context9000,
LLM_MAX_TOKENS4096. DeepSeek теперь обслуживает этот alias моделью V4.1 Flash;
это зафиксированная на дату документация, не pin на неизменяемые веса.
Независимый judge — gpt-4.1-mini, получает реально обрезанные `block.text`,
а не полные chunks за пределами контекста. Смена модели приложения/промпта не выполнялась.

## Итог с учётом исправления немецкого fixture

- 23/23 сценария с ожидаемым отказом завершились отказом.
- 74 answerable, из них 2 лишних отказа; 72 полученных ответа оценены judge.
- Judge: 70/72 faithful и 70/72 correct. Автоматический judge не равен ручной
  экспертизе и сам может ошибаться; неверные ответы ниже проверены против golden.
- Запрещённых меток в retrieval не обнаружено ни в одном из 99 исполнений.
  Это проверка прежней ролевой модели на synthetic corpus, **не тест изоляции аккаунтов**.
- V2 retrieval: 55/57 answerable имеют все expected documents в top20.
  Access set: 17/17, с повторно проверенным актуальным немецким документом.
- Начальный прогон: P50 1.93s, P95 4.22s, max11.39s от начала query pipeline
  до окончания ответа (включает query embedding, не включает judge).
  Это малая локальная выборка с concurrency3, не production SLO/load certification.

## Ограничения исходного renderer

`v2-results.md` / `access-results.md` — сохранённый вывод существующего harness.
Термин `no_answer` там объединяет разные категории ожидаемых отказов.
Его «citation precision» вычисляется через возвращённые source documents и golden,
не является отдельной проверкой опоры каждого утверждения на процитированный текст.
Не использовать это число как доказательство точной precision цитирования.
Автоматическая рекомендация threshold построена на маленькой выборке и не применялась.
Фраза renderer «отказ за $0» означает отсутствие LLM-генерации; embedding запроса
тоже платный и учтён в spend.json.

Не проверены этим прогоном: HTTP middleware/auth/SSE disconnect, создание аккаунтов,
денежная квота приложения, ingest/suggestions provider costs, performance production,
весь golden v2 и prompt injection/adversarial corpus. Это отдельные пункты аудита.
